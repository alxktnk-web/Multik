- `Repository.createProject(a,b)` always creates a new experiment, atomically storing a versioned list of slots in the project. Each slot contains stable identity and asset IDs; production RNG is independent of cover generation. Equal lengths use each asset once, unequal lengths use balanced repetitions. Validate assets before storing. Legacy projects without recipes retain their exact modular traversal and pair keys. New project/slot compositions are isolated even if assets repeat; existing favorite snapshots and legacy pair IDs remain resolvable. No schema upgrade or deletion.
- `Navigation.open(project, space)` opens existing projects without regeneration. `step` traverses recipe slots. `select` changes only the current slot source and retains existing source-replacement semantics; no neighbor changes. Self-mix is explicit UI action `Use twice`.
- `Navigation.resume()` restores last editing session including Library draft, layer and space at save boundaries. Expose `Navigation.resumeAvailable(): Promise<boolean>` for UI. Ordinary browsing must not replace last editing session. No writes during pointer movement or lift. Failed saves keep RAM state.
- Roll cover recipe is stored through `Repository.preference`/`setPreference` under `roll-cover:<rollId>`; recipe records version, asset IDs, normalized rectangles and crop. UI owns generation and persistence, reuses same six IDs in selected strips, shows a recoverable warning if persistence fails. Concurrent generation must not overwrite a persisted recipe: coordinator will provide atomic `ensureRollCover` if needed. No source blob copies.
- UI uses existing `ImportRoll.open` for single roll; selection mode retains first selection after import. Selecting an already-selected roll deselects; third selection prompts to deselect first; self mix uses explicit action. Mix button guards double tap and retries failures. Existing project card opens existing project.
