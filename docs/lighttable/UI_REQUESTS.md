## UI-ALG-001 — явное сравнение и выбор профиля пары

- Статус: **proposed**
- Дата: 20.10.2026
- Автор/направление: алгоритм изображения
- Ветка: `research/film-rendering`; commit/PR — история этой ветки
- Профиль: `lighttable-clean-v1`, version 3; формулы в IMAGE_ALGORITHM.md
- Нужен для пользовательского доступа к кандидату; математика и harness работают без UI.

### Причина

Profile 3 меняет света, цвет и распределение halo. Нельзя менять вид старых
пар молча или использовать Halo/Contrast для скрытого выбора алгоритма.
Нужны сравнение одинаковых inputs/геометрии/effects/seed и отдельный явный выбор.
См. `film-comparisons/` после завершения A/B-проверки.

### Предлагаемое пользовательское поведение

В Pro компактное дискретное действие `Image profile` / aria-label `Image profile`.
Варианты `Original (2)` и `Film candidate (3)` с пометкой experimental.
Иконка — предложение двух перекрывающихся кадров; окончательный дизайн за UI-чатом.
В обычном browse постоянный control не добавлять. Краткое A/B должно возвращать
исходный вид при отмене; не сохранять временный просмотр как принятую правку.
Portrait/landscape: доступно одной рукой, focus/VoiceOver сообщают активную версию.
Этот PR не реализует кнопку, панель или жест.

### Контракт алгоритма

`Composition.profile = { id: 'lighttable-clean-v1', version: 2 | 3 }`.
Дискретный выбор, без единиц/диапазона drag. Default 2; 2 является возвратом к v8,
а не выключением рендера. Profile 1 сохраняет прежнюю нормализацию в 2.
Остальные effects и их шкалы/границы/defaults остаются без изменений.
Выбор 3 управляет общей кривой и source-edge halo; новых регуляторов нет.
Halo strength=0 полностью выключает halo в обоих профилях.

### Жесты и состояние

Предлагается tap/select, без one-axis/XY назначения. Изменение только активной
пары, один законченный выбор — один Undo; отмена возвращает прежний профиль.
Во время активного drag/pinch/export не менять snapshot. Повторное открытие
показывает сохранённую версию. Сохранять по существующим metadata boundaries,
не вводить autosave на lift. При CAS/quota error оставлять draft/Undo и retry.

### Совместимость и стоимость

DB schema не меняется. Старые пары и новые default-пары остаются на 2.
v8 validator не читает version 3: до долговечной активации объяснить ограничение
отката; предпочтителен forward fix, исходные blobs всегда остаются.
Renderer получает только uniform версии; source masks одинаковы и переиспользуются,
дополнительных GPU textures/compilation при выборе нет. JPEG использует immutable
snapshot. Существующий thumbnail guard composition/revision/profileVersion
подходит; UI-чат обязан проверить stale thumbnail и экспорт при переключении.

### Работа без изменения UI

`node scripts/lighttable-film-check.mjs` задаёт profile 3 только тестовым
композициям на отдельном localhost origin. Runtime уже умеет рендерить explicit
snapshot version 3. В production нет скрытого способа включения, нового default,
URL-флага, жеста или массовой миграции.

### Критерии приёмки для UI-чата

Сравнение при одинаковых параметрах; 2→3→Undo возвращает 2; соседняя пара не
меняется; reload сохраняет явно выбранную версию; старый thumbnail не показывается
для нового профиля; lifted gesture не пишет DB; отмена и ошибка не теряют правки
или JPEG. Preview/JPEG соответствуют выбранному snapshot. На iPhone проверить
VoiceOver, достижимость controls, Safari/PWA цвет, память и скорость отдельно.

### Решение и реализация

Пока не согласовано; статус proposed не даёт разрешения на реализацию.

### Дополнение 20.10.2026 — третий вариант для плотных теней

Статус остаётся **proposed**, UI не реализован. Пользователь попросил дополнительный
профиль после profile 3. Предлагаемый список: `Original (2)`, `Film candidate (3)`,
`Dense candidate (4)`. API version: `2 | 3 | 4`, default по-прежнему 2.
Версия 4 усиливает разделение теней **обоих исходников до смешивания**, затем
использует tone/halo 3. Никакой скрытой привязки к существующему Contrast,
никаких новых диапазонов/жестов. Контроль предподготовки только A/B и ручные
маски не входят в этот runtime; они лишь показаны в исследовательских таблицах.

Визуальное сравнение 3↔4 при прежних параметрах должно быть обратимо и локально
для пары. Светлые источники по luminance≥.4 не меняются на стадии предподготовки;
очень тёмные детали могут исчезнуть. При user Contrast<1 прежняя кривая всё равно
поднимает чёрный: UI-чат не должен маскировать это переназначением control.
Ограничения сохранённых новых версий/отката, thumbnail revision/profile guards
и hardware приёмка из основной заявки относятся также к 4.
