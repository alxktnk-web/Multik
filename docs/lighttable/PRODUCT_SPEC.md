## Назначение и объекты

Multik складывает свет двух фотографий и позволяет независимо настроить их
взаимное положение и входную светлоту. Пользователь импортирует две плёнки,
просматривает пары в Mixes, сохраняет понравившиеся состояния в Library и
экспортирует итоговую фотографию. Редактирование параметрическое: импортированные
оригиналы не переписываются.

| Объект | Требование и текущая реализация |
| --- | --- |
| Roll | Набор импортированных источников; длина 6 / 12 / 24 / 36. Оригинальный Blob, preview и thumbnail имеют разные роли. |
| Mix | Сессия двух плёнок. Свайп в View одновременно перемещает оба индекса на один слот с циклическим переходом; выбор кадра в боковой ленте меняет один источник. |
| Pair | Конкретные два источника внутри сессии. Геометрия, Levels, профиль и эффекты сохраняются отдельно для каждой пары. |
| Library variant | Неизменяемый сохранённый полный редактируемый снимок состояния с фиксированными двумя источниками; оригиналы общие с Mix, JPEG не заменяет модель. |
| Working draft | Правки сохранённого варианта. При первой успешной границе сохранения создаётся отдельная рабочая копия; исходный вариант Library сохраняет прежнее состояние. |

Реализация: [navigation.ts](../../src/lighttable/model/navigation.ts),
[repository.ts](../../src/lighttable/data/repository.ts),
[types.ts](../../src/lighttable/data/types.ts).

## Просмотр и навигация

У Mixes и Library отдельные прямые кнопки. В Mixes свайпы перебирают пары,
в Library — только сохранённые варианты. Правка варианта и последующий reload
сохраняют контекст Library. Снятие сердца оставляет изображение на экране до
следующего свайпа; пустая Library сохраняет текущий вид, единственный вариант
не подменяет рабочие правки своим исходным снимком.

Portrait всегда служит для просмотра: свайпы, поворот всей композиции на 90°,
сердце, Save. Перенос, pinch и Levels в portrait не редактируют слои. Поворот
телефона меняет интерфейс независимо от ориентации самой композиции. Возврат
из landscape в portrait использует штатную границу сохранения; ошибка записи
оставляет draft в памяти и показывает ошибку.

Короткий неподвижный tap по фото в View скрывает обычные элементы управления
и ленты в обеих ориентациях; следующий tap возвращает их. Размер и положение
фото сохраняются. Свайп продолжает навигацию по текущему пространству.
Долгое касание, движение, pinch, отменённый жест и инструменты редактирования
не включают clean view. Ошибки и уведомление Removed · Undo остаются доступны.

В Library View ленты скрыты. Move / Levels / Halo показывают лишь два текущих
источника для выбора активного слоя; заменять источник варианта нельзя.
В landscape Mixes доступны полные боковые ленты.

Реализация: [workspace.ts](../../src/lighttable/ui/workspace.ts),
[gestures.ts](../../src/lighttable/input/gestures.ts),
[film-rails.ts](../../src/lighttable/ui/film-rails.ts).

## Landscape и инструменты

В landscape редактор доступен автоматически. Слева одна колонка из десяти
действий: Mixes, Library, View, Move, Levels, Halo, сердце, Save, поворот
композиции, Looks. Looks — последнее действие и единственное раскрываемое меню.
Отдельной видимой кнопки Undo правок, Done/Cancel или вложенного Pro нет.

Справа постоянно зарезервирована колонка 44 CSS px; stage имеет постоянный
внешний отступ 12 px. Переключение инструмента или скрытие лент Library не
изменяет геометрию фото. Шкалы Levels/Halo используют доступную высоту рядом
с фотографией. Цель удобства — области касания от 44 px; текущая компактная
колонка уменьшает кнопки на коротких landscape-экранах, см. KNOWN_ISSUES.

| Инструмент | Требование и реализованное поведение |
| --- | --- |
| View | Закрывает регулировки, блокирует изменение слоя drag/pinch, допускает свайпы и clean tap. Вход проходит через границу сохранения; при сбое draft остаётся. |
| Move | Только здесь drag переносит выбранный слой, pinch масштабирует его в пределах 0.5–4; viewport не становится отдельным редактируемым объектом. |
| Levels | Три точки black/mid/white входной светлоты CIELAB L* выбранного слоя. Точки не пересекаются; перемещение endpoints сохраняет относительный midpoint. Это не три RGB-кривые. |
| Levels gesture | Треть видимого фото при touch-down выбирает точку, вертикальное движение меняет её; справа также доступна длинная шкала. Выбор слоя и повторный выбор инструмента сохраняют Levels. Pinch не изменяет масштаб. |
| Halo | Прямая регулировка силы halo. Radius/threshold/XY не представлены отдельными пользовательскими инструментами текущей версии. Clear отключает Halo. |
| Looks | Original / Film / Dense / Clear соответствуют версиям профиля 2 / 3 / 4 / 5. Выбор закрывает меню. Clear сохраняет ручные Levels/геометрию; сложение может клиппироваться в белый. Новая пара начинается с Original. |

## Сохранение состояния и сердце

Завершение жеста оставляет правку в RAM. Во время прогретого движения и при
отпускании пальца не выполняются commits композиции, JPEG encoding или GPU
readback. Рендер обновляется через scheduler; metadata сохраняются на явных
границах: навигация, View/выход, сердце, экспорт, переход в portrait и Update.
Ошибка сохранения удерживает draft и блокирует зависимый переход/экспорт.
При конфликте ревизий доступно сохранение отдельной копии в Mixes.

Сердце относится ко всему состоянию, а не только к двум source ids. Изменённое
состояние можно сохранить новым вариантом. Повторное сохранение идентичного
состояния не создаёт второй membership. Правки Library не перезаписывают
сохранённый вариант: до следующего сердца это рабочая копия.

Unlike снимает только membership в Library и не удаляет оригиналы или снимок.
Уведомление Removed · Undo доступно 8 секунд в коллекции и workspace и
восстанавливает точный снятый вариант. Это отмена удаления из коллекции;
она не заменяет внутреннюю историю правок. Draft до успешной границы не
гарантированно переживает принудительное закрытие Safari.

Реализация: [session.ts](../../src/lighttable/model/session.ts),
[navigation.ts](../../src/lighttable/model/navigation.ts),
[repository.ts](../../src/lighttable/data/repository.ts),
[favorite-notice.ts](../../src/lighttable/ui/favorite-notice.ts).

## Импорт

Новая плёнка и новый Mix каждый раз начинают с 12 кадров; варианты 06 / 12 /
24 / 36 выбираются кнопками. Mix собирается из двух плёнок равной длины.
Next Roll открывает второй picker в том же пользовательском нажатии; Expose
запускает импорт. До Expose обе подборки остаются в RAM без записи источников.
Для отдельной плёнки подтверждение — Add roll.

Подтверждение доступно при точном количестве кадров. Лишние выбранные файлы
остаются видимыми для удаления; молчаливого обрезания нет. Ошибка/отмена job
сохраняет выбранные файлы для исправления и retry; завершённая плёнка при retry
Mix переиспользуется. Есть прогресс Importing X of Y и очистка только временных
данных собственного job.

Системное iOS-меню источников, порядок действий и кнопка Done принадлежат iOS.
HTML file input не обещает Photos-only picker или системный жёсткий лимит N.
Поддержка конкретного формата зависит от декодера браузера.

Реализация: [import-roll.ts](../../src/lighttable/ui/import-roll.ts),
[import.ts](../../src/lighttable/data/import.ts).

## Save to Photos и качество

Один Save сначала сохраняет dirty metadata, затем готовит JPEG и открывает
native Share. Экран экспорта, выбор размера, дополнительный preview и Download
не входят в текущий интерфейс. Размер — 4000 px по длинной стороне,
4000×3000 или 3000×4000 по повороту композиции; JPEG quality 0.95.

Экспорт заново рендерит зафиксированный snapshot из оригинальных Blob, а не
из уменьшенного экранного preview. В рамках текущего экспортера это максимум
качества: он ограничен 4000 px, использует браузерный decode/SDR JPEG и не
обещает исходное разрешение любой фотографии, RAW, lossless или сохранение HDR/P3.
При нехватке ресурсов выводится ошибка без тихой замены на 2000 px.

Если Safari теряет user activation за время подготовки, готовый JPEG остаётся
в RAM. Следующий tap по тому же Save вызывает Share до первого await без
повторного рендера. Отмена native sheet проходит тихо; выбор Save Image остаётся
действием пользователя в системном меню. Браузер без file Share получает
понятный статус недоступности.

Реализация: [export-dialog.ts](../../src/lighttable/ui/export-dialog.ts),
[renderer.ts](../../src/lighttable/render/renderer.ts),
[assets.ts](../../src/lighttable/render/assets.ts).

## Границы базы и дальнейшая работа

Lighttable живёт на `/lighttable/` со своей IndexedDB `multik-lighttable` и
scoped PWA. Classic на `/` сохраняется отдельно. Update появляется только
при ожидающем worker, применяет безопасную границу и не вызывает самовольного
reload при готовом обновлении. Публикация кода не является backup фотографий.

Не входят в этот срез: переключение root на Lighttable (M10), remote sync,
восстановление незаписанного RAM draft после убийства процесса, исходное
разрешение сверх 4000 px и возвращение прежнего UI Pro/Cancel/Done. Legacy
rendering parity/migration (M7) отменена владельцем; наличие старого кода или
исторической матрицы не возобновляет это требование.

По записи PROGRESS для runtime `c771eb8` прошли 109 unit tests, production
build, orientation/viewer и связанные favorite/Levels browser suites. Это
исторические результаты текущего runtime, а не новые запуски при написании
спецификации. Реальные iPhone/Safari, точность пальцем, Photos share,
HEIC/HDR/P3, нагрев, память и аппаратная плавность остаются открытой приёмкой.
Chromium emulation и SwiftShader не подтверждают эти свойства.

## 27 October 2026 — rolls and experiments (development branch)

Rolls are reusable and imported independently. Mixes are separate experiments: each new mix stores its randomly generated, balanced source-pair slots; navigating or reopening does not regenerate them. Existing projects without recipes retain their original modular navigation. Manual source selection changes the current slot. Self-mixing is explicit. The three home sections are Rolls, Mixes and Library; saved Library variants remain immutable and edited copies are drafts. Continue editing restores the last saved editing context, subject to save boundaries and storage errors.
