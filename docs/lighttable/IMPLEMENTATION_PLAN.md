## Актуальное дополнение 20.10.2026

Этот раздел заменяет прежние D11/D12, G2/G5 и пункты плана о viewport zoom/always-drag. Default browse: горизонтальный свайп переключает обе плёнки на один слот; move включается миниатюрой слоя, повторным tap или ↔ возвращается browse. ## 0. Что делать и чего пока не делать

Исторический исходный запрос был на план. После него владелец разрешил локальную реализацию M0–M4. Этот раздел не отменяет последующие команды; актуальное состояние см. PROGRESS.md. Публикация пока не выполнялась.
Начинать реализацию после следующей команды владельца. Не принимать этот документ сам по себе за команду на реализацию.

Цель: ощущение двух прозрачных фотографий, которые рукой перемещают по световому столу. Сначала обеспечить предсказуемую геометрию и отзывчивость; затем оформить интерфейс. «Никаких лагов» — цель, а не доказанный факт: производительность принимается на настоящем iPhone.

Рекомендуется отдельный новый интерфейс и интерактивный рендер рядом с работающей v1. Не переписывать всё приложение за один заход, не превращать старый main.ts в новый монолит. Сохранить полезную математику, шейдеры, формат исходников, экспорт и исправления Safari. Не вводить React/Preact/WebGPU/сервер ради этой задачи.

Приоритеты: сохранность фото → однозначность жестов → плавность → качество изображения → минималистичный вид → дополнительные эффекты.

### Наблюдения, которые определяют архитектуру

1. Developer.renderFrame() каждый раз вызывает gl.readPixels(), создаёт ImageData и переворачивает строки CPU. Viewer затем делает putImageData и drawOriented. Это потенциально дорогая синхронизация GPU→CPU→canvas, а не измеренное единственное узкое место.
2. При движении сейчас возможны декодирование нужных соседних фото и перестройка композиции. Нужны готовые текстуры и ограниченный кэш, а не декодирование на каждом pointermove.
3. main.ts заменяет содержимое экранов через innerHTML. Новая рабочая поверхность должна жить постоянно; изменение параметра не должно пересоздавать canvas и контекст.
4. Поворот вида и сдвиг слоя уже разделены, но сдвиг управляет только x. Верхняя лента имеет recipe.vShiftMm; это ещё не индивидуальная вертикальная правка текущего кадра.
5. input[type=file] блокируется только при busy, не при достижении длины. Обработчик добавляет все полученные файлы. Это реальный дефект импорта.
6. Старый IndexedDB открывается с version 1. Повышение версии этой же БД сломает открытие старой программой при откате (VersionError).

## 2. Контракт интерфейса

### 2.1 Обычный просмотр результатов

- Максимальная площадь фотографии; вписывание целого кадра, без скрытого crop ради заполнения экрана.
- Один палец двигает активный слой по x и y, без обязательного удержания и без определения намерения по скорости.
- Активный слой выбирается двумя миниатюрами исходников. Последний выбранный слой активен; по умолчанию верхний.
- Два пальца масштабируют И перемещают область просмотра. Масштаб не изменяет композицию/экспорт.
- Решение для v2: один палец в режиме «слой» двигает слой и при увеличенном виде; для перемещения увеличенного вида используются два пальца. Это намеренное отличие от v1, где один палец при увеличении панорамирует просмотр. Не оставлять скрытую зависимость от масштаба.
- Перелистывание — исключительно по ленте результатов или выбором её миниатюры. Быстрое движение внутри фото не листает.
- В портрете лента снизу. Потянуть её за выделенную область вниз — свернуть; язычок снизу раскрывает её. Можно также тапнуть по язычку.
- В landscape лента слева, прокручивается вертикально, сворачивается к левому краю. У скрытой ленты остаётся заметный язычок с зоной касания не менее 44×44 CSS px.
- Состояния видимости лент раздельны для портрета/landscape; prefs не являются правками кадра.
- Перемещение панели не должно конкурировать с прокруткой миниатюр: handle раскрывает/скрывает, тело ленты выбирает/прокручивает.
- На фото остаются минимальные значки: назад, миниатюры слоёв, поворот, редактор. Undo появляется после правки. Экспорт доступен компактным действием, не постоянной большой панелью.
- Ни одного ползунка/названия параметра в обычном режиме.

### 2.2 Ручной подбор пары (новый режим)

- В landscape слева миниатюры плёнки A, справа плёнки B, в центре композиция.
- Тап по миниатюре заменяет соответствующий источник. Последняя выбранная сторона становится активной.
- Тап по уже выбранной миниатюре лишь переключает активный слой, ничего не сбрасывает.
- Скролл каждой ленты просматривает миниатюры и НЕ меняет источник. Источник меняется только явным выбором.
- Для портрета тот же режим работает: две узкие строки A/B в раскрываемом нижнем лотке. Их можно спрятать вместе. Полный режим не привязан жёстко к ориентации устройства.
- Поворот телефона перестраивает панели, НЕ включает ручной режим и НЕ выбирает новую пару.
- Вход в ручной режим — маленький значок двух плёнок. Режим и выбор пары сохраняются отдельно от ориентации.
- Одна пара соответствует отдельной композиции. Возврат к ней возвращает её сдвиги. В первой версии одна рабочая композиция на пару внутри сессии; функция нескольких вариантов одной пары — отдельное будущее улучшение.
- Пара упорядочена: A:a + B:b не равна A:b + B:a. Ключ включает id сессии, обе плёнки, оба фото, версии источников; не только индексы.
- При первой встрече новой пары стартовое положение фиксировано. Не переносить незаметно сдвиги предыдущей пары на новый снимок.
- Изменение пары фиксирует прежние изменённые параметры; не создавать полноразмерный JPEG для каждого пробного сочетания.
- «Избранное» отмечает удачные сочетания; листание само по себе не засоряет библиотеку сотнями готовых JPEG.

### 2.3 Professional mode

- Маленький значок редактора открывает компактную полоску категорий: слой, свет, ореол, цвет.
- Выбор категории показывает только необходимые значки параметров, а не всю панель с крутилками.
- Активный параметр обозначается кольцом/контуром; остальные приглушены.
- После выбора параметра движение пальца вверх/вниз по фото меняет его относительно значения при pointerdown.
- В одноосном режиме горизонтальное движение не назначать скрытой функции.
- Двухосные пары вводить только после работоспособного одноосного режима: яркость/контраст, сила/радиус ореола. Двухосность включается явно отдельным значком, а не автоматически при отклонении пальца.
- Диапазоны и шкалы определяет единый registry, общий для жестов, доступности и сериализации. Яркость — EV, радиус — положительная логарифмическая шкала, сила/контраст — ограниченная нормализованная шкала.
- Стартовый пример чувствительности: 70% высоты рабочей области проходит полный диапазон параметра. Уточнить по устройству, хранить в registry; никаких magic numbers по обработчикам.
- В XY-режиме X и Y независимы. Небольшая мёртвая зона 4–8 CSS px при начале; после неё абсолютный delta от начала жеста, без накопления ошибки.
- Во время касания можно показать тонкую дугу или крест с точкой; после отпускания убрать. Не накрывать фото графиками и числами.
- Значок слоя возвращает перемещение фотографий. Закрытие Pro возвращает обычный режим. Pinch остаётся навигацией вида, не меняет параметры.
- Смена инструмента во время активного жеста запрещена до отпускания/отмены.
- Видимые подписи параметров по умолчанию отсутствуют, но aria-label, VoiceOver, фокус и короткие сообщения ошибок обязательны. «Без текста» не означает немые ошибки потери данных.
- Все редкие старые настройки при необходимости доступны в раскрываемой расширенной части Pro; не переносить весь старый редактор поверх нового canvas одновременно. На первом пилоте неподдержанные редкие инструменты остаются в Classic.

### 2.4 Визуальные правила и библиотека

- Фон #2C2926, поднятые поверхности примерно #35312D, текст/значки #E6E0D7, шалфей #A3B2A0. Цвета уточняются по устройству.
- Никакого чисто чёрного основного фона, кислотных акцентов и большого размытия на всю поверхность.
- Полупрозрачное стекло на маленьких элементах, статическая заливка при prefers-reduced-transparency. Движение UI учитывает prefers-reduced-motion.
- Не оставлять fixed noise overlay и большую ambient blur анимацию поверх интерактивного canvas без измерений стоимости.
- Главная: последний результат крупной обложкой, ниже стопки плёнок, компактный плюс; две выбранные плёнки обозначаются контурами, действие смешивания становится доступно.
- Имена, даты, переименование/удаление — по раскрытию карточки. Счётчики фото не убирать ради минимализма.
- Empty state: две полупрозрачные карточки и добавление, без длинной инструкции. Первое использование может иметь одноразовую короткую подсказку жеста; не постоянную надпись на кадре.
- `design/concept.png` — концепция материалов и компоновки, не пиксельная спецификация. На ней ещё нет всех поздних решений про две боковые ленты и Pro.
- Размеры touch targets ≥44 CSS px, safe-area на всех сторонах. Фотография не попадает под Dynamic Island/жест Home; не жертвовать точным касанием ради тонкого значка.

### 2.5 Импорт и переполнение плёнки

- Системный iOS picker не поддерживает надёжный max-count через обычный HTML file input. Не обещать заблокировать 13-е выделение внутри системного окна.
- В приложении поддерживать точный инвариант: committed roll.photos.length == выбранной длине.
- При N/N отключать и label/button, и file input; дополнительно проверять лимит в обработчике. После удаления снова включать.
- Получили больше оставшихся мест: временный экран отбора с миниатюрами, явный счётчик, подтверждение только при допустимом количестве. Не брать первые N молча и не удалять файл без явного решения.
- Поддерживать pending candidates отдельно от уже принятых фото. Все новые кандидаты доступны для выбора; при большом наборе не декодировать сразу полноразмерные изображения.
- N/N — спокойная галочка и выключенный плюс. N+K/N — предупреждение цветом и текстом; цвет не единственный сигнал.
- Уменьшение длины ниже уже принятого количества тоже требует отбора. Увеличение длины сохраняет выбранные фото.
- После ошибки декодирования можно заменить проблемное фото и повторить, не теряя остальные.
- На стадии импорта нормализовать ориентацию один раз; исходники не перезаписывать при движении/повороте в редакторе.

`UI / Pointer Events → Session commands → Draft + revision → Render snapshot → GPU`.
Отдельно: `Navigation / explicit Save → Repository commit → derivative queue`.
Рендер не пишет в БД. БД не управляет canvas. Геометрия не читает DOM. UI не меняет WebGL-ресурсы напрямую.

## 4. Модель состояния и данных

### 4.1 Разделить четыре вида состояния

1. **Composition** — долговечное описание результата: источники, трансформации слоёв, эффекты, ориентация, seed, revision.
2. **Draft** — изменяемая рабочая копия текущей композиции; история жестов, dirty/revision; только RAM до границы сохранения.
3. **Viewport** — масштаб/панорамирование просмотра, размеры доступной области, DPR. Не влияет на экспорт.
4. **Chrome/preferences** — видимость лент, выбранный инструмент, ориентация компоновки. Не часть фотографии.

### 4.2 Минимальные типы (схема, не готовый код)

```ts
type LayerId = 'a' | 'b';
type QuarterTurns = 0 | 1 | 2 | 3;
type SourceRef = { assetId: string; assetRevision: number };
type LayerTransform = { xMm: number; yMm: number; turns: QuarterTurns };
type SourcePlacement = { source: SourceRef; rect: RectMm; turns: QuarterTurns; gain: number };
type Layer = {
  id: LayerId;
  placements: SourcePlacement[]; // один источник в manual; несколько в legacy strip
  transform: LayerTransform;
  tone: LayerTone;
  anchoredGlows: SourceAnchoredGlow[];
};
type Composition = {
  schema: 1;
  id: string;
  revision: number;
  mode: 'manual-pair' | 'legacy-frame';
  origin?: { developmentId: string; frameIndex: number; baselineHash: string };
  pairKey?: string;
  frame: { widthMm: number; heightMm: number; turns: QuarterTurns };
  layers: [Layer, Layer];
  profile: { id: 'legacy-m-v1' | 'lighttable-clean-v1'; version: number };
  effects: EffectSettings;
  seed: number;
};
type Session = {
  id: string;
  mode: 'results' | 'manual';
  currentCompositionId: string;
  activeLayer: LayerId;
  draft: Composition;
  savedRevision: number;
  gesture: GestureState;
  viewport: Viewport;
  tool: ToolState;
};
```

Добавить полную валидацию прочитанных записей: конечные числа, допустимые id, диапазоны, версия schema. Не сохранять texture, canvas, pointer, File URL или DOM в Composition.

### 4.3 Совместимость с текущей плёнкой

Не подменять старую двойную экспозицию двумя случайно выбранными картинками: в старом кадре могут присутствовать части соседних снимков.
Адаптер legacy строит размещения ровно из makeRecipe + storedEdit + frame index; переводит абсолютную координату ленты к локальному окну кадра. Прежние сдвиги и повороты учитывает ровно один раз.
У каждой группы A/B может быть несколько SourcePlacement. Общая новая трансформация группы относится только к выбранному выходному кадру. Соседние выходные кадры используют свои Composition, общий рецепт не мутируется.
В manual режимах A/B содержат по одному выбранному источнику и не подтягивают соседние снимки автоматически при движении.

Старые JPEG показывать без пересчёта до явного редактирования/создания копии v2. При открытии в v2 наследовать старый look, зерно, glow и прочие параметры. Чистый новый профиль применять только к новым ручным композициям. Если адаптер ещё не воспроизводит старый профиль, оставить такой кадр read-only и открыть Classic для его редактирования, а не незаметно менять вид.

### 4.4 История

Один законченный жест = один шаг Undo. pointermove не создаёт сотни шагов. Снимок параметров до жеста; на end — финальный шаг, на cancel — возврат к началу жеста. Удерживать разумный лимит, например 50 шагов текущей сессии, без копирования фото.
Повторное движение начинается от текущего положения. Смена активного слоя не сбрасывает предыдущий слой. Простой tap без движения не меняет параметры, не создаёт Undo и не ставит dirty.

## 5. Координаты и физическое поведение

- Каноническая плоскость кадра: 36×27 мм для совместимости с текущими рецептами. Экранные CSS px, backing pixels и film mm — разные единицы.
- Для каждой сцены строится явная цепочка: Source UV → orientation/fit source → placement → local layer transform → frame view rotation → contain-fit → viewport zoom/pan → CSS screen.
- Повороты source, старого Placement.turn и целого кадра имеют разные соглашения в текущем коде. Привести их к одному каноническому соглашению через адаптер и тесты, не менять знак на глаз.
- Перенос от pointer delta: умножение вектора `[dx,dy,0]` на обратную линейную часть матрицы film→screen. Translation не должна влиять на вектор. Не четыре разрозненных if по повороту в каждом компоненте.
- При zoom 2× сдвиг пальца на 20 CSS px должен сместить изображение на те же 20 экранных px, а не на 40. Экспорт хранит соответствующий меньший сдвиг в film mm.
- В shader используется та же матрица слоя, что и в hit testing/экспорте. Не дублировать формулы в CSS, TypeScript и GLSL без общего источника.
- При смене ориентации телефона/размеров рабочей области активный жест завершить по явному правилу: отменить только текущий незавершённый жест, сохранить прежний draft, пересчитать viewport; не продолжать со старым anchor.
- Нет инерции у фотографий, магнита к чужому слою, непредсказуемого выравнивания, случайного нового seed. Палец отпустили — плёнка остановилась.
- Ограничения translation держать в канонических единицах. Для manual стартовый предел ±ширина/высота кадра; оставить доступный Reset/Undo. Не ограничивать до нуля только ради избегания открытого края.
- За границей одного снимка нет растяжения крайних пикселей: слой имеет маску покрытия, через отсутствие покрытия виден второй слой. Texture CLAMP_TO_EDGE не должен превращаться в полосы по краям.
- Если оба слоя уведены, остаётся пустая область композиции. Рекомендуемый однозначный default: отсутствие экспозиции даёт чёрный участок результата, как у текущего складывания света; тёплый серый стол существует снаружи кадра и не запекается в JPEG. Не включать auto-crop/генеративное заполнение/растягивание. Это художественное решение проверить на пилоте; alpha PNG — отдельная будущая возможность.
- Поворот всего кадра меняет view/export orientation без повторного поворота и JPEG-кодирования исходников. Телефон landscape сам не меняет frame.turns.

## 6. Арбитр жестов — один владелец события

Состояния: idle, pendingTap, layerDrag, parameterDrag, viewportGesture, railScroll, railCollapse, navigating, exportBusy. Ортогонально — текущие режим и инструмент.

| Начало | Действие | Что нельзя делать |
|---|---|---|
| 1 pointer на фото, tool=layer | после небольшого порога 3–5 px перемещение A/B | листать результат по скорости |
| 1 pointer на фото, tool=parameter | менять активный параметр | одновременно двигать слой |
| 2 pointers на фото | отменить незавершённый одно-пальцевый жест, pinch + pan | сохранить draft, поменять эффект |
| после pinch остался 1 pointer | дождаться отпускания всех пальцев | внезапно начать layer drag этим пальцем |
| pointer на ленте | скролл / тап миниатюры / навигационный свайп ленты | менять изображение |
| pointer на handle ленты | раскрыть/свернуть | выбрать фото |
| pointercancel / lost capture | откатить текущий жест к его началу | сбросить предыдущие жесты сессии |
| navigation while save pending | одна сериализованная транзакция; последний запрошенный target либо игнор повторов | конкурирующие записи и прыжок без сохранения |

Выбрать и задокументировать один вариант повторной навигации: рекомендовано блокировать переходы до завершения короткого metadata commit. Не держать блокировку во время GPU preview или фонового thumbnail.

Pointer capture на рабочем canvas; touch-action:none только там и на специальных handles, не на всем документе. Для обычных лент использовать native scrolling где возможно. Не использовать браузерный edge-back gesture как необходимый способ управления.
Системное меню фотографии не должно перехватывать drag. Не назначать long-press на фото обязательной функции, конфликтующей с началом движения; экспорт доступен отдельной кнопкой.

## 7. Рендер: сначала убрать синхронизацию с CPU

### 7.1 Один видимый WebGL canvas

Живой preview рисовать прямо на видимый canvas. В интерактивном пути запрещены gl.readPixels, ImageData, putImageData, toDataURL, toBlob, JPEG encode и запись IndexedDB.
Использовать общий вычислительный конвейер сцены и две конечные операции:
- `present(scene, viewport, quality)` — GPU/FBO → default framebuffer;
- `export(sceneSnapshot, outputSpec)` — offscreen target → редкий readback/encode по явной задаче.

Не создавать «быстрый фильтр CSS» для жеста и другой алгоритм для экспорта: картинка не должна менять смешивание или halo при отпускании пальца.
Старый Developer.renderFrame оставить для Classic. Новый путь может переиспользовать shader/pass функции; если общие функции меняются, сохранять старые значения по умолчанию и регрессии.

### 7.2 Планировщик кадров

- Pointer event обновляет несколько чисел draft и номер revision, отмечает dirty render. Не выполняет тяжёлую работу.
- Один requestAnimationFrame loop на рабочую поверхность. Не создавать rAF для каждого pointermove.
- За кадр рисовать последнее состояние. Промежуточные события можно отбросить. Очередь устаревших рендеров не копить.
- На отсутствие изменений loop засыпает; остановить при hidden/background.
- Async source loading идёт отдельно. Каждая загрузка несёт session id + selection revision + context generation. Результат от старой пары/контекста освобождается, а не заменяет текущую картинку.
- Сначала обе новые текстуры готовы, затем атомарно переключить render scene. Пока loading — остаётся последняя целая композиция и маленький индикатор. Нельзя случайно показать A новой пары с B предыдущей.
- Не перерисовывать весь DOM; обновлять transform uniforms, class активного значка и небольшой индикатор.
- Не сериализовать весь draft через JSON.stringify и не structuredClone на каждом move. Полные snapshots только на gesture boundaries, navigation, export; hot path — числовые поля + revisions/dirty masks.

### 7.3 Текстуры, исходники и кадры рядом

- Для активной пары/кадра текстуры загружены до начала жеста. Изменение x/y не вызывает decode/upload.
- Prepared source cache по assetId + assetRevision + resolution tier + цветовой политике. Один pending promise на ключ.
- Предзагрузка только ближайших вероятных источников, низкий приоритет, ограничение по памяти. Не загружать 24/36 оригиналов в GPU сразу.
- Миниатюры лент — самостоятельные маленькие ресурсы, виртуализировать длинные списки; не полноразмерные sources.
- Кэш с byte budget, не только с числом элементов. Активные источники pinned; фоновые LRU освобождаются первыми. Задачи выгрузки не трогают текстуру, использующуюся текущим кадром.
- Разделить decoded bitmap cache и GPU texture cache; освобождать ImageBitmap.close после upload, если копия больше не нужна.
- Компилировать shader programs и готовить FBO до первого drag. Не создавать контекст при каждом выборе фото/параметра.
- Уменьшенные previews допустимо кэшировать в БД при импорте/подготовке, но не в pointer loop.

### 7.4 Кэш эффектов и ореол

Новый профиль `lighttable-clean-v1`: сложение экспозиций в линейном свете + стабильный вывод SDR + красный halo ярких объектов. Сохраняем характер двойной экспозиции: не заменять его CSS opacity/multiply из-за метафоры прозрачных плёнок. Начальные weights 1/1, balance через существующий balanceGains (sum=2), unit pass gain; точный neutral shoulder закрепить как versioned profile на визуальном M2 review. См. DECISIONS.md D09. Dust, grain, hair, endFog, случайные leaks и самостоятельный общий bloom выключены. Не менять автоматически исходную экспозицию кадра от количества движения.

Ореол выделяется по ярким областям каждого источника ДО смешивания: два средних по яркости слоя не должны давать случайный красный ореол только от суммы. Существующие look/threshold функции — отправная точка, не повод менять старый профиль.

- У каждого источника или группы есть подготовленные bright-mask / blur textures.
- Чистый перенос слоя не меняет исходные pixels, threshold, radius или mask. Переносить изображение и его подготовленный halo одной геометрией.
- Halo за пределами source поддерживать padding; не обрезать его жёстко прямоугольником исходника. Нужен эталон пересчёта композиции для сравнения.
- Если source-level caching не совпадает с reference из-за порядков тональных операций/границ, сначала корректный низкоразмерный GPU recompute; ускорять только измеренный bottleneck. Не жертвовать математикой ради заявленного кэша.
- Halo strength меняет uniform. Radius/threshold/exposure, влияющая на выделение светов, инвалидирует соответствующий источник/уровень. Balance/gain — явно указать порядок относительно threshold и одинаково применять в preview/export.
- Случайность — небольшой seeded множитель/вариация зафиксированного эффекта, только от id композиции + seed. Никакого Math.random в draw/pointer.
- Ореол полностью отключается нулём; при этом не остаётся скрытый bloom.
- Wand-маска привязана к asset/source UV. Выбор объекта один раз строит/кэширует маску; перенос не запускает CPU flood-fill заново.
- Старые glows, заданные в координатах выходного кадра, при адаптации преобразовать к конкретному покрывающему source и UV. Если однозначной привязки нет, сохранить старую семантику в legacy профиле и явно обозначить ограничение, не угадывать объект.

### 7.5 Качество и бюджет

Начальные, НЕ измеренные на телефоне ориентиры:
- движущийся preview: длинная сторона 1024 px, DPR ограничен 1–1.5;
- спокойный preview: до 1536 px после 120–200 ms без жеста, если хватает ресурсов;
- после начала следующего жеста опять быстрый tier; без изменения вида, seed и геометрии;
- при недостаточной частоте адаптация 1024→768→512 с гистерезисом; не менять размер FBO в каждом кадре;
- начальный budget интерактивных ресурсов ~96 MiB; уточнять после подсчёта всех allocations, не выдавать за системный лимит Safari;
- 60 fps — целевой режим на согласованном iPhone; устойчивые 30 fps допустимы только как явно проверенный fallback, а не как скрытое выполнение критерия 60 fps.

Считать: RGBA8 = w*h*4, RGBA16F = w*h*8, mipmap примерно +1/3, все FBO/источники/CPU decoded copies. Размеры GL queried caps, framebuffer completeness и восстановление контекста обязательны. Не обещать «12 MP всегда» по результатам SwiftShader.

Без gl.finish и синхронного readPixels для измерения FPS. CPU timings, rAF intervals, long tasks при поддержке, EXT_disjoint_timer_query_webgl2 при наличии. Не спутать время выдачи GL commands с завершением GPU. Timestamp input→rAF — лишь приближение задержки, не измерение photons-to-finger.

OffscreenCanvas/worker не является обязательной зависимостью v2. Сначала прямой WebGL main thread без CPU readback. Worker для декодирования/подготовки подключать только после профиля, с feature detection и рабочим main-thread fallback Safari. SharedArrayBuffer/COOP/COEP не добавлять ради архитектурной красоты.

## 8. Сохранение без паузы на JPEG

### 8.1 Что означает сохранение

Источники + сериализуемая Composition являются первичными данными. JPEG/thumbnail — производные, восстановимые результаты.

- pointerup: обновить RAM draft/undo, НЕ писать IndexedDB и НЕ создавать JPEG.
- Свайп по result rail / выбор другой пары / выход из просмотра / переход в редактор / явный экспорт: commit изменённых параметров текущего результата.
- Нет изменений — нет записи.
- Commit записывает только небольшой immutable snapshot параметров и revision. Не ждёт полноразмерного GPU рендера.
- После успешной транзакции можно перейти к следующему кадру. Старый черновик можно отпустить после подтверждения.
- Thumbnail/экспорт имеют `(compositionId, revision, profileVersion, outputSpec)` в ключе; устаревшая задача не затирает новый результат.
- Thumbnail ставить в background idle queue. Если пользователь снова двигает фото — приостановить/отложить. До готовности использовать старую миниатюру с маленьким индикатором или нейтральную заглушку.
- Full JPEG создавать по явному Save/Share либо отдельной пакетной задаче после взаимодействия; не на каждую навигацию.

### 8.2 Ошибка/конфликт/закрытие

- При quota/transaction error не переходить, держать draft и undo, показать короткую ошибку с retry. Не очищать библиотеку автоматически.
- Атомарный compare-and-swap по revision внутри короткой readwrite транзакции: ожидаем сохранённую ревизию N → пишем N+1. Если другая вкладка уже записала N+1, не last-write-wins. Сохранить черновик и предложить отдельную копию/перезагрузку версии.
- IndexedDB transaction не держать открытой через decode, encode, network или await произвольной задачи. В транзакции только чтение/проверка/запись связанных записей.
- Не рассчитывать, что pagehide/beforeunload успеет асинхронно сохранить данные на iOS. В v2 первой версии незавершённый draft до навигации остаётся RAM-only согласно требованию владельца. Закрытие/перезагрузка вкладки может потерять текущую несохранённую правку; исходники и уже сохранённые композиции остаются.
- Не вводить скрытый autosave на pointerup «для надёжности». Если позже понадобится crash-recovery checkpoint, отдельно согласовать, отличить recovery от committed revision и проверить I/O вне жеста.

## 9. БД, исходники и настоящий откат

### 9.1 Изолировать данные

Старая БД `multik-app` остаётся version 1 и не меняется из v2. Новая БД — `multik-lighttable`, своя schema version. Object stores: assets, assetPreviews, rolls, sessions, compositions, derivatives, importJobs, prefs (детали по реальной необходимости).

Для старой библиотеки — readonly reader. Пользователь выбирает нужные две плёнки; перед долговечной работой в v2 они копируются в собственные assets/rolls по одной/небольшими порциями, без повторной JPEG-компрессии и без eager decode всех originals. Показать один понятный этап подготовки; не выдавать холодный импорт за лаг жеста.

Почему нужна копия: старая программа не знает, что её исходник используется новой композицией. Если хранить только ссылку в legacy DB, удаление в Classic могло бы сломать v2.

- Не дублировать всю библиотеку заранее, только принятые выбранные плёнки; детерминированный ключ происхождения позволяет не копировать их повторно.
- Legacy фото неизменяемы при существующем контракте: ключ `(legacy DB, rollId, photoIndex)` достаточен для идентификации исходной записи, с проверкой метаданных/размера. Не хешировать 100 MB на главном потоке ради дедупликации каждого жеста.
- importJobs отмечает прогресс; незавершённый импорт не появляется готовой плёнкой. Повторный запуск продолжает/откатывает только свои staging assets.
- Оригинал не удаляется. При нехватке места сообщить, сколько нужно приблизительно, и дать отменить подготовку; никаких скрытых чисток.
- На iPhone это расходует дополнительное место выбранных плёнок. Изоляция данных — сознательная цена безопасного пилота. Недублирующее совместное хранилище рассматривать только после стабилизации и отдельной схемы совместимости.
- Удаление в v2 проверяет свои ссылки. Физические blobs удаляются только когда нет ни одного владельца/композиции/активного importJob. Не удалять исходники из legacy DB.
- Локальные архивы кода НЕ содержат фото пользователя. Данные Safari остаются на устройстве; кодовый rollback не является backup фотографий.

### 9.2 Доставка рядом со старой версией

Рекомендуемый пилот: старая v1 остаётся на `/`, v2 открывается на `/lighttable/` того же origin. Один проект Sites и прежний owner-private доступ. Отдельный домен не использовать: origin меняет доступ к IndexedDB.

- Собирать v2 в отдельный staging каталог со своим index, manifest, scope `/lighttable/`, start_url `/lighttable/`, уникальным manifest id и service worker `/lighttable/sw.js`.
- В общий artifact сначала распаковать неизменный baseline build v1 в root, затем добавить каталог lighttable. Все root файлы baseline должны совпадать по checksum.
- НЕ запускать старый scripts/pwa.mjs поверх объединённого дерева: он рекурсивно включит v2 в precache старого SW и нарушит изоляцию. Отдельные сборки/отдельные precache lists, потом assembly без повторной генерации root SW.
- Старый worker обслуживает whitelist baseline assets и должен пропускать неизвестные /lighttable запросы. Проверить первый переход под root worker до регистрации нового, а не предполагать идеальную изоляцию.
- Cache prefixes привязаны к scope; v2 activation удаляет только свои кэши. recovery удаляет/обновляет только нужную регистрацию, никогда IndexedDB.
- Сохранить нормализацию redirect responses, проверку content-type/URL и защиту от кэширования login HTML в ОБОИХ worker paths.
- Новые версии не перезапускают приложение во время жеста, несохранённой правки, импорта или экспорта. Обновление предлагается в безопасном состоянии.
- На пилоте заход в v2 по отдельной ссылке, возврат в Classic — через небольшое меню. Не менять автоматически установленную старую PWA.
- После проверки на iPhone можно обсуждать основной адрес v2. Перенос default на `/` — отдельный этап, не включён автоматически в первый выпуск.

### 9.3 Откат

1. Быстрый пользовательский возврат: открыть `/` — работающая v1 с прежней БД. Новые v2-правки остаются в v2 и не отображаются в старом редакторе; это ожидаемо.
2. История исходников: baseline commit + `baseline/repository.bundle`, source.zip и готовый production.tar.gz уже сохранены.
3. Хостинг: при необходимости повторно развернуть сохранённый Sites version_id из BASELINE.json; не создавать новый сайт и не делать force-push старого HEAD поверх нового.
4. Полный возврат к baseline artifact уберёт /lighttable/ из онлайн-файлов. Для установленных v2 PWA это не прозрачный откат: нужен переход на корень, а их worker может ещё держать v2 cache. Предпочтителен возврат через Classic при сохранённом dual artifact либо отдельная проверенная сборка возврата для v2.
5. Не удалять multik-lighttable и её assets при откате. Возобновить v2 можно позже. Не пытаться автоматически «понизить» новую БД в старую.
6. Пользовательские фото не отправлять в source repo, dist, публичные assets, тесты или ZIP передачи. Fixtures синтетические/разрешённые, browser profile изолированный.

## 10. Экспорт, цвет и отказоустойчивость

- Export получает immutable snapshot конкретной revision; дальнейший drag не меняет уже начатый экспорт.
- Та же сцена, порядок смешивания, tone mapping, halo, seed и source transforms. Preview tier меняет разрешение, не художественный алгоритм.
- Full resolution не запускается при pointermove или после каждого pointerup. Экспорт имеет собственное отменяемое задание и статус, а не блокирует скрытую очередь жестов.
- На первом GPU вертикальном срезе проверить текущую стандартную величину около 2000×1500. До заявления 12 MP реализовать/проверить ограничение памяти и tiled путь, если монолитные buffers выходят за бюджет.
- Tile rendering использует halo overlap не меньше максимального support radius всех фильтров; глобальные film coordinates для шума/масок; обрезка overlap при сборке, без швов. Сравнить целый и tiled рендер на маленьких эталонах.
- Финальный canvas/JPEG encoder тоже потребляет память: tiles не отменяют память на выходное изображение. Считать весь пик, освобождать ненужные preview caches, ограничивать выход и сообщать честную ошибку вместо silent downgrade.
- Preview и export сериализуются по GPU budget. Базовый вариант — один рабочий GL context и переключение задач; второй context/worker только при подтверждённом memory budget. Не держать два комплекта 12 MP FBO.
- Выходной baseline — SDR sRGB с согласованными decode/upload/output flags. P3/HDR/HEIC особенности проверять отдельно на реальных iPhone файлах, не обещать сохранение HDR без реализации.
- CSS warm gray и стекло не должны попадать в результат экспорта.
- Web Share на Safari требует user activation. Если подготовка JPEG закончилась поздно, показать готовый к отправке результат и дать второй явный tap Share; не терять готовый файл и не молча игнорировать NotAllowedError.
- Context loss: остановить draw, сохранить RAM draft/selection, восстановить programs/FBO/textures из assets, перерисовать ту же revision. Старые async результаты со старым context generation уничтожить.
- При отсутствии WebGL2/float targets показать понятное сообщение и ссылку Classic/просмотр сохранённых JPEG. Не обещать полностью эквивалентный CPU editor без отдельной реализации.

## 11. Этапы реализации и критерии выхода

Подробные проверяемые сценарии — `ACCEPTANCE.md`. Каждый этап — отдельный reviewable commit. Не начинать десять этапов одновременно. Отмечать фактическое состояние в PROGRESS.md, новый контекст начинает с него.

### M0. Изоляция и воспроизводимая база

Работы:
- Проверить checksum пакета, baseline commit, clean checkout и текущую версию сайта.
- Создать отдельный checkout/worktree и ветку `lighttable-v2`. Не редактировать original/main для экспериментов.
- Предпочтительно git worktree от baseline, если исходный repo доступен. Если остался только bundle — clone bundle в новую папку, создать ветку; origin из bundle является локальным файлом, НЕ пригоден для публикации. Sites remote/credential получить штатно перед будущей публикацией.
- Установить зависимости по lockfile, если отсутствуют. Исследовать AGENTS.md и актуальные skills. Не переносить старые секреты из чата/файлов.
- Воспроизвести `npm test`, build, browser и PWA baseline при наличии разрешённой среды. Невозможную проверку записать как pending, не PASS.
- Добавить отдельный v2 entry и сборку staging; Classic работает как раньше. Подготовить tests для неизменности baseline root artifact.
Выход: откат воспроизводим, старое приложение запускается, новый пустой entry не перехватывает его URL/БД/SW.

### M1. Геометрия и состояния без красивого интерфейса

Работы:
- types/session/transforms/commands, registry параметров и scene builder;
- модель двух слоёв, mm coordinates, обратные преобразования для 0/90/180/270°, zoom/pan;
- gesture arbiter: drag, cancel, two-finger viewport, undo, no-save-on-lift;
- две синтетические texture-grid картинки, простой canvas placeholder.
Тесты: чистая математика, знаки/масштабы, отсутствие drift, cancel текущего жеста, активный слой.
Выход: все преобразования имеют round-trip tests; ни одна функция геометрии не зависит от DOM/БД.

### M2. Вертикальный срез «световой стол» — главный технический рубеж

Работы:
- видимый WebGL canvas, direct presentation, rAF latest-state, подготовленные textures;
- реальные два источника, 2D drag, zoom, whole-frame rotation, активный слой;
- базовое смешивание + красный halo; быстрый preview без readPixels/encode/IDB;
- счётчики allocations/readbacks/texture uploads/render timings в dev-only diagnostics;
- качество 1024/768/512, memory accounting, cleanup/context-loss smoke.
Тесты: A1–A6, R1–R5; реальное iPhone измерение по PERFORMANCE protocol.
Выход: демонстрация двух подвижных фото с ореолом на телефоне. Если плавности нет, чинить профиль/рендер, а не добавлять новые панели. Остальную независимую документацию/инфраструктуру можно делать, но не объявлять runtime gate пройденным без устройства.

### M3. Надёжные composition commits и изолированные assets

Работы:
- отдельная БД, readonly legacy adapter, copy-on-adopt выбранных плёнок;
- repository с atomic metadata commit, CAS revision и retry без потери draft;
- ручная пара/legacy composition identity, история сессии;
- derivative queue с ревизиями, no full JPEG на навигацию;
- импорт v2 с N/N и overflow review.
Тесты: D1–D9, I1–I7, A7–A9.
Выход: после нескольких drag — ноль commit writes; при переходе — одна новая revision; reload возвращает сохранённое, v1 DB не изменена.

### M4. Две плёнки и минимальная рабочая поверхность

Работы:
- portrait/landscape layout, левая/правая source rails, result rail, handles;
- выбор/прокрутка/скрытие без конфликтов с canvas gestures;
- last-selected layer, возврат к прежней паре с её правками;
- async selection epoch, ограниченный prefetch, виртуализированные thumbnails;
- показ последней целой пары во время холодной загрузки.
Тесты: U1–U6, G1–G8; стресс 100 смен пары, ротация телефона в середине жеста.
Выход: можно работать только фото и пальцами, настройки закрыты, нет перепутанных пар и утечек памяти.

### M5. Professional mode без большой панели

Работы:
- icon strip и одноосные параметры сначала;
- режимы layer/parameter, indicator, undo, keyboard/VoiceOver equivalents;
- только после одноосных тестов — явные XY пары;
- параметрическая invalidation halo/source cache, без скачков при следующем касании;
- расширенные редкие настройки добавлять по необходимости, не копировать весь legacy editor в первый экран.
Тесты: P1–P7 и shader/cache invalidation.
Выход: пользователь всегда видит активный инструмент, движения не меняют одновременно слой и эффект.

### M6. Библиотека и визуальная доводка

Работы:
- тёплая палитра, photographic hero/stack cards, минимальные действия;
- доступные hit targets, safe-area, landscape и reduced motion/transparency;
- визуальные snapshots реальных состояний: empty, selected pair, rail hidden, Pro, import full/overflow/error.
Тесты: U7–U10, визуальный просмотр на iPhone. Декоративные effects проверить под нагрузкой.
Выход: подтверждённый вид без ухудшения M2 performance.

### M7. Совместимость со старыми проявками — отменено владельцем

Не реализовывать legacy rendering parity или миграцию ради выпуска. Старый код/данные остаются нетронутым backup. Следующий практический этап — M8.

### M8. Полноразмерный экспорт и память

Работы:
- export snapshot, thumbnails/output cache, явный Share flow;
- tile path/ограничения/отмена, GPU scheduling, context restoration;
- измерение 2000×1500 и около 4000×3000 на устройстве.
Тесты: E1–E7, memory stress, color/halo edges, failures.
Выход: экспорт соответствует композиции и не разрушает интерактивную сессию; неподдержанный размер явно сообщается.

### M9. Dual-version PWA и пилотная публикация

Работы:
- изолированные build/manifest/SW scopes и объединение без перепаковки baseline SW;
- upgrade/recovery/offline/auth regression для root и /lighttable;
- сохранить полный рабочий source state, push точного commit только в Sites source repo, artifact от этого commit;
- reuse project id/access, штатный Sites helper по актуальному skill. Credentials только RAM/stdin, без файлов/argv/лога;
- опубликовать v2 пилот по согласованной команде, дать URL /lighttable/ и явный возврат на root;
- проверить на устройстве сценарии засыпание/возврат, long gestures, pair browse, Pro, export.
Выход: терминальный успешный deployment, воспроизводимый rollback, real-device checklist. Не менять default root на v2 в этом этапе.

### M10. Принятие и переключение основной версии (отдельное решение)

Только после feedback владельца и закрытых hardware gates. Сначала проектировать миграцию установленной PWA/manifest/SW, затем менять default. Classic и v1 DB сохраняются, пока владелец явно не согласует иное. Автоматического удаления старых данных нет.

## 12. Правила для модели-исполнителя

- Следовать этому плану и последним указаниям владельца; противоречащие исторические markdown не являются истиной.
- Не обещать «без багов», «60 fps», «Safari проверен», пока нет соответствующего evidence.
- Не упрощать per-frame edits до глобальной мутации Recipe. Не сводить legacy strip к двум картинкам без проверки.
- Не лечить производительность снятием требуемых эффектов без объяснения. Сначала measurements и устранение GPU→CPU roundtrip.
- Не добавлять frameworks, backend, analytics, новые зависимости без конкретной необходимости; при добавлении фиксировать why и lockfile.
- Не запускать subagents автоматически, если пользователь/применимые инструкции этого не разрешили.
- Не ломать PWA recovery, не советовать очистку Safari data как обычный способ обновления.
- Не делать force push, reset --hard, удаление старой БД или перенос на GitHub.
- После этапа: один reviewable commit, что изменено/почему, checks и реальные ограничения, запись в PROGRESS.md. Обновить решения, если implementation требует отступления.
- Если контекст заканчивается, дописать PROGRESS/DECISIONS и дать следующему запуску точные пути/commit. Не начинать с нуля.
- В новом чате не предполагать доступ к прежнему filesystem, credentials и npm cache: проверить. Если их нет — восстановить из bundle/source archive; исходные фото пользователя там отсутствуют.
