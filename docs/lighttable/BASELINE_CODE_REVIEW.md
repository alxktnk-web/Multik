### P2 — сохранённый рабочий черновик Library теряет доступный путь открытия

**Статус: VERIFIED, Chromium + синтетические изображения.** Черновик не удаляется
и оригиналы не повреждаются: его изменения остаются в IndexedDB, но после
перехода к другому варианту их нельзя снова открыть через существующие коллекции.

Причина:

- [navigation.ts:25](../../src/lighttable/model/navigation.ts#L25) сохраняет
  изменённый Library-вариант отдельной working copy;
  [repository.ts:62](../../src/lighttable/data/repository.ts#L62) помечает проект
  `kind: 'draft'`.
- [library.ts:119](../../src/lighttable/ui/library.ts#L119) исключает все проекты
  с `kind` из Mixes. Library строится только из favorite memberships
  ([library.ts:124](../../src/lighttable/ui/library.ts#L124)); они продолжают
  указывать на неизменяемые исходные варианты, не на этот черновик.
- Следующий Library swipe открывает другой favorite
  ([navigation.ts:84](../../src/lighttable/model/navigation.ts#L84)) и заменяет
  `last-project`. Startup восстанавливает только `last-project`
  ([workspace.ts:181](../../src/lighttable/ui/workspace.ts#L181)).

Воспроизведение:

1. Создать Mix и сохранить два разных состояния в Library.
2. Открыть первый вариант, в landscape изменить слой, нажать View. Успешная
   граница сохраняет отдельный draft; исходный favorite остаётся прежним.
3. Не нажимая сердце для нового состояния, свайпнуть ко второму варианту.
4. Перезагрузить приложение и проверить Mixes, Library и повторное открытие
   первого варианта. Черновика в коллекциях нет; первый вариант показывает
   исходный сохранённый снимок.

Временный Playwright harness воспроизвёл те же шаги через текущие model API и
настоящие кнопки коллекций. После reload отдельная проверка IDB подтвердила
`kind === 'draft'` и сохранённый `layers[1].transform.turns === 1`; идентификатора
этого проекта не было ни среди Mixes cards, ни среди Library cards.

Влияние: пользователь видит успешное сохранение на границе View/навигации, но
после ухода из черновика не может вернуться к правкам через UI. Это проблема
восстановимости и навигации; она **не является удалением** сохранённых данных.
Reload продолжает черновик, пока он остаётся последним проектом. Сердце до
ухода сохраняет отдельный доступный вариант и служит текущим обходным путём.

Предлагаемое минимальное исправление в отдельной задаче: добавить явный путь
повторного открытия сохранённых `draft` проектов (например, раздел рабочих
черновиков), открывая их с Library-контекстом и фиксированными источниками.
Не менять favorite membership и не превращать черновики в новые likes.
Простое удаление фильтра `!p.kind` недостаточно: оно также покажет favorite
проекты и требует явного решения, в каком пространстве открывать draft.
Регрессия должна проверять уход, reload, повторное открытие черновика и
неизменность исходного favorite.

## Объём проверки и ограничения

Независимо прочитаны текущие PRODUCT_SPEC и основные пути Repository, Session,
Navigation, workspace, Gestures, Editor, Library/FilmRails, FavoriteNotice,
ExportDialog, Renderer/assets/Levels и scoped service worker/update. Проверены
границы сохранения, неизменяемые варианты, unlike/Undo, Library anchor после
draft/reload/removal, pointer lifecycle и snapshot/cache native Share.

Других конкретных дефектов с достаточными доказательствами в этих путях не
выделено. Зеленые существующие тесты не использовались как доказательство
корректности. Для приведённого сценария запущен новый временный harness вне
репозитория; использованы Linux Chromium, SwiftShader, Node `v24.19.0`, отдельная
эфемерная browser context и только синтетические фото. Репозиторий и тестовые
expectations не менялись. Полный PWA lifecycle и настоящий native Share в этом
обзоре не выполнялись; реальное устройство и данные владельца не использовались.
