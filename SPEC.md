# Мультик — ТЗ

Версия 1.5 · 14.10.2026 · согласовано с Александром в чате. 1.4: панель правки готового кадра, засветки на половине кадров трёх типов. 1.5: правка кадра — «пульт» с отдельными настройками нижней и верхней фотографии; один вид обработки; ♥ и «Сохранить» — разные кнопки.

## Идея

PWA для iPhone и компьютера (Safari, Chrome), которое имитирует плёночную двойную экспозицию. Пользователь выбирает
две пачки фото из своей медиатеки — первый и второй проход плёнки. Приложение перемешивает
кадры, выкладывает каждую пачку в длинную плёнку, накладывает вторую плёнку на первую
со сдвигом, «проявляет» и показывает результат в своей галерее. Понравившиеся кадры
пользователь сохраняет в Фото.

Принцип: никаких превью и ручной настройки. Выбрал, нажал, получил плёнку, смотришь
факты. Настройки есть, но спрятаны.

## Плёнки и проявки (решено 13.10.2026, заменяет сценарий «две пачки сразу»)

- **Плёнка — это один проход.** Александр «снимает» плёнку: выбирает фото (6/12/24/36),
  даёт название; плёнка сохраняется в библиотеке с номером, названием и временем.
  Плёнки копятся: плёнка 1, 2, 3, 4…
- **Проявка — это смешивание двух любых плёнок** из библиотеки: например, плёнка 1 как первый
  проход и плёнка 4 как второй. Порядок проходов можно поменять. Кадров — по короткой плёнке.
- Одну и ту же плёнку можно смешивать с разными партнёрами и проявлять сколько угодно раз.
  Каждая проявка сохраняется отдельно: какие плёнки, рецепт, вид, время, отмеченные кадры.
- Экраны приложения: **Плёнки** (библиотека, «+ Новая плёнка», выбор двух) → **Смешать**
  (проход 1, проход 2, ⇅, вид, «Проявить») → **Проявка** (кадры, отметки, «Сохранить в Фото»,
  «Проявить заново», «Плёнка полосой»). Дизайн-варианты — на холсте «Мультик — дизайн приложения».

## Пользовательский сценарий

1. **Плёнка.** Выбор длины: 6 / 12 / 24 / 36 кадров. Оба прохода одинаковой длины.
2. **Первый проход.** «Выберите N фото» → системный выбор фото iOS (множественный).
   Нужно выбрать ровно N; пока не выбрано, «Дальше» неактивна.
3. **Второй проход.** То же самое, ещё N фото.
4. **«Экспонировать».** Экран проявки с прогрессом (кадр k из N). Живого превью нет.
   Ориентир по времени: 12 кадров — меньше минуты, 36 кадров — 1–3 минуты.
5. **Галерея плёнки.** Готовые кадры. Действия:
   - листать кадры на весь экран;
   - отметить понравившиеся;
   - сохранить один кадр / выбранные / «Сохранить всю плёнку»;
   - вид «вся плёнка полосой» (лента целиком, с перемычками);
   - **«Проявить заново»** — те же две пачки фото, новое перемешивание, новый сдвиг →
     новая плёнка (старая остаётся).
6. **История.** Все проявленные плёнки хранятся в приложении, пока пользователь их не удалит.

### Сохранение в Фото

Веб-приложение не может писать в конкретный альбом. Сохраняем через Web Share API
(`navigator.share({ files })`) → «Сохранить изображения» кладёт в общую ленту.
Для отдельного альбома — быстрая команда iOS «Сохранить в Multik»
(Shortcuts: принимает изображения из меню «Поделиться» → «Сохранить в фотоальбом: Multik»).
Инструкцию по её созданию показываем в приложении.

## Геометрия плёнки

Все размеры в миллиметрах. Это «настоящая» плёнка, в пикселях считаем только на выходе.

| Параметр | Значение |
|---|---|
| Кадр | **36 × 27 мм** (4:3 — пропорция iPhone, длинная сторона как у 35 мм) |
| Перемычка между кадрами | **2 мм** |
| Шаг плёнки | 38 мм |
| Длина плёнки | N × 38 мм |
| Разрешение рендера | ≈ 111 px/мм → кадр 4000 × 3000 (12 Мп) |

- **Все кадры на плёнке горизонтальные.** Вертикальный снимок ложится в кадр повёрнутым
  на 90° **против часовой стрелки** — как будто камеру повернули при съёмке.
  Горизонтальный + вертикальный дают наложение крест-накрест — это нормально и желательно.
- **Без кадрирования.** Снимок вписывается в окно 36 × 27 целиком с сохранением пропорций
  (для 4:3 — ровно по окну; 16:9 — по длинной стороне; квадрат — по высоте 27 мм).
  Незаполненная часть кадра — неэкспонированная плёнка (ноль света).
- **Кадровое окно со скруглёнными углами** (радиус ~0,5–1 мм) и мягким краем
  (размытие ~0,2–0,3 мм). Скругление видно там, где внутрь кадра A заходит край кадра B.
- **Перемычка не идеально чёрная.** Плотность подложки + вуаль + зерно (тёмная, не #000);
  ореол и засветки переползают через неё; кадр B, попавший на перемычку A, виден там
  одиночной экспозицией. Внутри пересвеченного кадра перемычка B видна как **более тёмная
  полоса** (там свет попал один раз) — это получается из сложения света само.
- **Одиночная экспозиция богаче двойной.** Там, где кадр B не заходит, картинка A плотнее
  и насыщеннее, двойная зона — светлее и дымчатее. Тоже следствие сложения, отдельно
  не рисуем.
- **Концы плёнки.** Из-за сдвига часть первого или последнего кадра остаётся одиночной
  экспозицией. Зацикливания нет: части плёнки B за пределами плёнки A теряются.

### Сдвиг второй плёнки

- **Сдвиг по длине** — вся плёнка B сдвигается целиком, со всеми перемычками; сдвиг
  постоянный для всей плёнки (протяжка 35 мм идёт по перфорации).
  В настройках — ползунок **от −36 до +36 мм** (влево / вправо, максимум — длина кадра).
  По умолчанию «Случайно»: модуль сдвига **чаще 5–15 мм** (край кадра B виден в правой
  или левой трети кадра, как на референсах), изредка больше; знак случайный.
- **Разброс протяжки** — независимый люфт каждого кадра второго прохода, ±0,5–1 мм,
  **не накапливается** (кадр привязан к перфорации).
- **Вертикальный сдвиг и перекос** — по умолчанию почти ноль (доли мм, доли градуса):
  плёнку держат направляющие кадрового окна.

### Film swap (две независимые галочки)

- **«Перевернуть вторую плёнку»** — каждое изображение второго прохода повёрнуто на 180°,
  порядок кадров не меняется. **По умолчанию включено** (на 5 из 6 референсов Александра
  вторая экспозиция перевёрнута).
- **«Обратный порядок»** — кадры второго прохода идут задом наперёд, сами изображения
  не поворачиваются. По умолчанию выключено.

## Перемешивание

1. Каждая пачка перемешивается отдельно (Fisher–Yates, ГПСЧ с сидом).
2. Пачка A выкладывается в плёнку A, пачка B — в плёнку B.
3. Плёнка B сдвигается и накладывается на A.

Пары не выбираются чистым рандомом: они получаются из порядка кадров и сдвига.

**Рецепт проявки** сохраняется вместе с плёнкой: сид, итоговые порядки кадров, сдвиги,
все случайные события (засветки, пыль, разброс экспозиции), настройки и версия алгоритма.
Готовые результаты после обновления приложения автоматически не пересчитываются.

## Как считаем изображение

Главное правило: **свет складывается.** Наложение 50/50 или «Экран» не используем,
считаем в линейном свете и пропускаем сумму через плёночную кривую.

Честно: фото iPhone уже обработаны телефоном (сжатие светов, подъём теней, резкость),
поэтому линейное сложение — хорошая основа имитации, а не физическая точность.
«Portra 400 + заметный красный ореол» — авторский профиль, а не копия конкретной плёнки.
Вид подбирается на тестовом наборе и референсах (см. «Эталоны»).

### Входной цветовой конвейер

1. Прочитать снимок с его цветовым профилем (у iPhone — Display P3), учесть EXIF-ориентацию.
2. Привести к одному рабочему пространству (линейный, P3-гамма), не считая любые числа sRGB.
3. HDR: проверить, доступна ли в браузере HDR gain map снимка iPhone (реальная информация
   о светах ярче белого). Если да — использовать её для светов; если нет — эвристика (шаг 2 ниже).
4. На экспорте — явно выбранный профиль (Display P3 или sRGB), одинаковый в галерее и в Фото.

### Порядок обработки

| Шаг | Что | Где применяется |
|---|---|---|
| 1 | Линеаризация (см. конвейер выше) | каждый снимок |
| 2 | Расширение светов — **ограниченное**: мелкие яркие контрастные пятна считаем ярче белого; большие светлые поверхности (стена, облако) почти не трогаем. Эвристика, подбирается на примерах | каждый снимок, **до сложения** |
| 3 | «Объектив»: лёгкое виньетирование, лёгкая мягкость | **каждый снимок отдельно**, до сложения |
| 4 | Разброс экспозиции: каждый кадр каждого прохода ±1/3 ступени случайно | каждый снимок |
| 5 | Укладка на плёнку: поворот, вписывание, сдвиг, кадровое окно со скруглёнными углами и мягким краем | каждый снимок |
| 6 | Сложение A + B. По умолчанию **пересвет** — без компенсации. Сумму **не обрезаем** до кривой и **не нормализуем** яркость каждого кадра — проявка фиксированная для всей плёнки | лента |
| 7 | **Засветки** (light leaks) и **засветка концов плёнки** — добавляются как свет | лента |
| 8 | **Ореол (halation)**: линейное рассеяние суммы (несколько радиусов ~0,5–2 мм в мм плёнки), тонировка в красно-оранжевый. По умолчанию **заметный** | **вся лента**, переползает через перемычки |
| 9 | Мягкое «дыхание» светов (рассеяние в объективе/скане) — слабее и светлее ореола | лента |
| 10 | Плёночная кривая Portra 400: поканально, в плотностях негатива; мягкое плечо (света теплеют и выцветают), мягкие тени, приподнятый чёрный (вуаль) | лента |
| 11 | Зерно — **один раз**, в плотностях, многомасштабное, зависит от экспозиции (на пересвеченном мельче); привязано к координатам плёнки | лента |
| 12 | Едва заметная неравномерность проявки (низкочастотная пятнистость плотности) | лента |
| 13 | Пыль и волоски (как на скане) | кадр |
| 14 | Перевод в выходной профиль, нарезка по сетке плёнки A | выход |

Порядок шагов 2 и 8 важен: нелинейное выделение источников идёт **в каждом проходе
отдельно**, а рассеяние — **линейное, на сумме**. Так два средних по яркости участка
не «зажигают» ореол только из-за сложения.

Что одно, а что удваивается:

- **На каждый проход:** объектив, виньетирование, мягкость, разброс экспозиции.
- **Один раз** (свойства плёнки, проявки, скана): засветки, ореол, кривая, цвет, зерно,
  неравномерность проявки, пыль.

### Засветки (light leaks)

По референсам — главный источник «красного»:

- Большие мягкие пятна **красно-оранжевого → малинового** цвета, входят **от края кадра**
  (чаще вертикальной полосой у левого/правого края), бывают с более резкой границей там,
  где свет прошёл вдоль кадрового окна.
- По умолчанию — **примерно на половине кадров**, разной силы (решение Александра 13.10.2026, заменяет «1 из 5»):
  много слабых, несколько заметных, редко разрушительные. Частота — крутилка Leaks в «Смешать».
- **Три типа** (по разбору ChatGPT): бледный широкий подсвет (Glow), насыщенная красно-малиновая полоса от края
  (Stripe), выжженный край с рваной цветной границей (Burnt edge). Каждая четвёртая садится на перемычку
  и заходит на соседний кадр — одно событие на ленте. Свет неоднородный, «живой».
- Добавляются как свет до кривой, поэтому в засветке картинка выцветает естественно.

**Засветка концов плёнки** (по умолчанию включена): первый и/или последний кадр плёнки
частично засвечен — белое поле с рваным красно-оранжевым краем (референс 4).

### Пыль и волоски

По умолчанию включены, умеренно: мелкие белые точки (пыль на негативе) и изредка тонкий
волосок или царапина. Регулируется в настройках.

## Пульт — 1.5, решено 14.10.2026 (заменяет раздел 1.4 ниже в части интерфейса)

- **Один вид обработки** (M «Melted»), пока способ не утверждён; выбор видов и лишние кнопки убраны.
  Меньше текста, больше графики (сообщение Александра 14.10.2026).
- **Пульт правки кадра**: сверху превью, ниже три канала — **Bottom** (снимок первой плёнки),
  **Top** (снимок второй), **Mix** (общее). У каждого снимка свои ползунки вдоль экрана на всю ширину (свет, контраст, чёрное, белое,
  свечение), крутилки (цвет, тепло, мягкость) и поворот шагами по 90° — **всё до наложения**, поэтому видно, как
  настройка одного снимка меняет их взаимодействие. Mix: баланс (ползунок с миниатюрами по краям: влево — сильнее
  нижний снимок, вправо — верхний, ±3 ступени, общая яркость та же). В пульте нигде нет цифр — только положение регуляторов, слияние белого, ореол, засветки, общий контраст и
  чёрное; зерно, пыль, мягкое свечение; кубик — новая засветка. Сдвиг верхней плёнки (14.10.2026): крутилка Shift
  крутится пальцем вверх-вниз (вверх — больше), ≈1 мм на пиксель — можно доехать до любого кадра второй плёнки;
  ползунок без значка под балансом — подстройка, весь ход — от кадра назад до кадра вперёд. Сдвиг и баланс — свои у
  каждого кадра; у неправленых кадров — значения проявки.
  Двойное касание регулятора — значение проявки. Живой пересчёт; меняются только последние шаги —
  пересчитывается только кривая.
- **Перед проявкой**: верхняя и нижняя плёнки стопкой (⇅ — поменять, нажатие на верхнюю — поворот 180°),
  крутилки «сдвиг» (по умолчанию случайно), «засветки», «белое», переключатель 12 Мп, Develop. Сверху — живой образец: кадр из случайной пары снимков двух плёнок меняется, пока крутишь (кубик — другая пара). Крутилки крутятся движением пальца вбок (вправо — больше), полный ход ≈ 500 px.
- **Гало у светлых предметов** (14.10.2026, по фото Александра с «светящимися кроссовками»): в пульте кнопка
  ✦ Glow. Режим **Spot** — касание фото ставит мягкий круг (радиус, сила); внутри круга светятся только светлые
  места, гало расползается и за круг. Режим **Wand** — касание светлого предмета выделяет его по яркости
  (чувствительность, сила). Источник — снимок Bottom, Top или оба; цвет гало — общий (оранжевый ↔ красный).
  Точки можно двигать пальцем, удалять. Гало — свет до кривой: белое ядро и широкий цветной ореол трёх радиусов.
- **Просмотр**: три небольшие кнопки — ♥, «Сохранить» (одно нажатие открывает меню iOS «Сохранить
  изображение»: веб-приложению Apple не даёт сохранить в Фото совсем без меню), пульт. «Проявить заново»,
  «Сохранить избранное», «Удалить» — в меню «…».

## Правка готового кадра (Edit) — 1.4, решено 13.10.2026

В просмотре проявки кнопка **Edit** открывает панель, где видны и меняются все настройки, применённые к кадру
(просьба Александра; дизайн утверждён по макету «Multik — Edit panel»). Правило «без живого превью» относится
к созданию плёнки; **в правке кадр пересчитывается живьём** (решение Александра 13.10.2026).

- **Basic** — четыре крутилки, как в Фото: баланс проходов A ↔ B, экспозиция, слияние белого, сила засветок.
- **Overlay** — баланс (±2 ступени, сумма света постоянна — формула ChatGPT), сдвиг второго прохода в этом кадре,
  поворот второго прохода; свет: экспозиция, слияние белого, ореол, «дыхание» светов.
- **Leaks** — засветки кадра пронумерованы на снимке: включить/выключить (форма сохраняется), тип, сила, ширина,
  цвет (оранжевый → малиновый), край; «Another variant» меняет только рисунок выбранной засветки;
  «Add leak» добавляет случайную; «Remove».
- **Tone** — кривые: общая (по яркости, без сдвига цвета) и R/G/B; чёрная точка, контраст, насыщенность,
  тепло светов. Кривые — после основной тональной функции, в видимой шкале.
- **Texture** — зерно, пыль и волоски.
- «Original» (держать) — кадр до правок; отмена/повтор; Reset у каждого раздела.
- Кадр пересчитывается **из исходных снимков**, а не из готового JPEG; правка хранится поверх рецепта,
  исходный кадр проявки сохраняется рядом — Reset возвращает его. Соседние кадры не меняются.
- Предпросмотр — в уменьшенном размере; Done проявляет кадр в полном размере проявки.

## Эталоны (для разработки, не для приложения)

## Выход

- N кадров, нарезанных по сетке плёнки A: 36 × 27 мм → **4000 × 3000 px**, JPEG ~0,92.
- Чистый кадр: **без перфорации, номеров и надписей** на краю.
- Отдельно — вид «вся плёнка полосой» в уменьшенном разрешении, с перемычками.

## Техника

- **PWA**: манифест, service worker, работает офлайн, устанавливается на экран «Домой».
  Хостинг — GitHub Pages (HTTPS).
- **Всё локально, без сервера.** Фото никуда не уходят.
- **Импорт**: `<input type="file" accept="image/*" multiple>` → системный выбор фото.
  HEIC и JPEG, профиль цвета, EXIF-ориентация. Целевое устройство — iPhone 16 Pro: основная
  камера по умолчанию снимает 24 Мп HEIC (в режиме 48 Мп / ProRAW — больше). При импорте
  уменьшаем до 4000 px по длинной стороне.
  Проверяем, что выбрано ровно N и **все файлы прочитались**; ошибочный или нечитаемый
  снимок можно **заменить по одному**, не выбирая пачку заново. Учитываем фото, которые
  iOS сначала скачивает из iCloud (без интернета могут быть недоступны).
- **Хранение**: IndexedDB. Запрашиваем постоянное хранилище (`navigator.storage.persist()`),
  проверяем результат и свободное место, обрабатываем нехватку места.
  Исходники — общие рабочие файлы пачек; каждая проявка — отдельные результаты + рецепт,
  без копирования исходников. Удаление одной проявки не ломает остальные.
  Хранение в браузере не гарантировано навсегда — важные кадры сохранять в Фото.
- **Обработка**: WebGL2, half-float текстуры (линейный свет > 1.0); поддержку форматов
  проверяем при запуске. Все 72 снимка в память не помещаются, поэтому идём **скользящим
  окном** по ленте: кадр A, 1–2 перекрывающих кадра B и поля по краям на радиус ореола.
  Один буфер RGBA16F 4000 × 3000 ≈ 96 МБ — бюджет памяти считаем по всем буферам
  и проверяем на iPhone 16 Pro; при нехватке — обработка меньшими частями.
  Ореол и зерно считаются в координатах ленты, поэтому на стыках нет швов.
- **Устойчивость к прерыванию**: план плёнки (рецепт) сохраняется до начала проявки,
  каждый готовый кадр записывается сразу. После сворачивания, перезагрузки или потери
  графического контекста проявка продолжается с того же места с тем же перемешиванием.
  На работу в фоне не рассчитываем. Время проявки (1–3 мин на 36 кадров) — ориентир,
  проверить на устройстве.
- **Сохранение**: Web Share API с файлами по действию пользователя; проверка `canShare`,
  файлы готовятся заранее; отмена ≠ ошибка; при ограничениях — партиями. Успешный вызов
  share не гарантирует появление в Фото — проверяем на устройстве. Альбом через быструю
  команду iOS — дополнительная возможность, не основа сценария.
